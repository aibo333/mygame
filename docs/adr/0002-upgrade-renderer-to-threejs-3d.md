# ADR-0002: 將渲染層從 Phaser 3 (2D) 升級為 Three.js (3D 俯視角 ＋ TPS 雙視角)

- **狀態**：已採納（Accepted）
- **日期**：2026-11-23

## 背景（Context）

在 v0.2（ADR-0001）轉向《戰意》式「武將手操 ＋ 兵團指揮」後，團隊評估長期視覺與玩法潛力：若希望未來能支援類似《逃離鴨科夫》／《殭屍毀滅工程》的立體俯視角，甚至平滑切換為《戰意》本體的肩後第三人稱（TPS）或 FPS 視角，2D 渲染層（Phaser 3）將無法直接承接。

同時，由於 `src/core/` 核心戰鬥引擎已完全與視圖層解耦，趁 Phase 1 尚未投入大量 2D 美術資產前替換渲染層的成本最低。

## 決策（Decision）

1. **以 Three.js 取代 Phaser 3 作為 `src/game/` 渲染層**：
   - `src/core/` 與所有 15 項 Vitest 單元測試維持 **100% 不動**，核心戰鬥演算仍在穩定的 `(x, z)` 平面執行。
   - 保留 `BattlefieldController` 公開介面（並擴充 `setCameraMode('tactical' | 'tps')`）。
2. **支援雙視角即時切換（`Tab`）**：
   - `tactical`：3D 斜俯視戰術視角（利於指揮兵團列陣與觀察全局）。
   - `tps`：《戰意》肩後第三人稱視角（強化動作代入感與遠景攻城張力）。
3. **預留標準 `.glb` 外部 3D 模型替換接口**：
   - 預設採用程式化 Low-Poly 3D 角色與立體城牆，並於 `src/game/models3d.ts` 預留 `GLTFLoader` 載入鉤子，未來可直接替換為合法授權的 `.glb` / `.vrm` 資產而不必更動核心邏輯。

## 影響（Consequences）

- **正面**：零核心重寫即獲得立體城牆、動態光影陰影、雙視角切換與未來轉 TPS/FPS 的擴展能力；且建置產物體積較 Phaser 3 更精簡。
- **代價**：需維護 3D 地面 Raycast 瞄準與 TPS 鏡頭防城牆遮擋邏輯。
