# ADR-0005: 核心玩法定案（隨機街區 × 裝甲火車撤離 × 屍潮 × 周回養成）與外部現成素材管線

- **狀態**：已採納（Accepted）
- **日期**：2026-11-25
- **取代／修訂**：修訂 [ADR-0004](0004-art-pivot-anime-chibi-lol-camera-ruins-train.md)（放棄自製 3D 資產管線與三人小隊即時切換，改採單人直控 × 外部現成素材 × 碼圖分離；並正式確立單局撤離與周回成長核心循環）。

## 背景與決策（Context & Decision）

在原型實測中發現，由程式碼／AI 從零生成 3D 場景與角色模型的產出效率過低、視覺品質難以穩定，且三人 AI 跟隨小隊會分散操作注意力與增加尋路維護成本。同時，遊戲核心目標需要收斂為具體、可反覆遊玩且適合單人開發推進的玩法閉環。

因此決定進行以下四項架構與設計定案：

1. **核心玩法循環（隨機地圖 × 裝甲火車基地 × 限時任務撤離 × 屍潮 × 周回養成）**：
   - 每局基於隨機種子生成一張模組化都市街區，裝甲火車停靠於邊緣鐵軌作為出發點、補給暫存點、防禦陣地與唯一撤離載具。
   - 玩家在限時與逐步升級的屍潮壓力下搜刮資源、完成主線任務並守住發車倒數以撤離。
   - 周回成長聚焦於兩條清晰主軸：**收集並編組 NPC 乘員進駐列車崗位**，以及**強化裝甲火車模組（裝甲、砲塔、引擎、軍械與貨倉）**。
2. **單人直控取代跟隨小隊**：
   - 局內僅由玩家操控單一角色，聚焦走位、瞄準、翻滾與撤離決策；NPC 角色轉為周回收集與火車崗位支援（砲塔操控、維修、醫療、偵查、後勤），避免 AI 隊友卡地形或干擾戰鬥節奏。
3. **外部現成素材 ＋ 模型／動作解耦管線**：
   - 放棄 `tools/art_pipeline/` 自產 3D 模型路線，改用 **Kenney Retro Urban Kit**（CC0 模組化街區）支撐隨機地圖生成。
   - 角色模型與動作完全分離：透過 Godot 4 原生 `SkeletonProfileHumanoid` 與 `BoneMap`（`*.tres`）將 **Adobe Mixamo** 真人動捕庫重定向至任何標準人形骨架；原型階段暫用免費動漫模型驗證，未來商業化可零動作重做無痛替換角色資產。
4. **碼圖分離異地開發工作流（GitHub × Google Drive）**：
   - GitHub Repo 僅追蹤程式碼、場景、文件、測試與 Godot `*.import`／`*.tres`（鎖定骨架與匯入設定），大型二進位資產透過 `tools/pack_assets.py` 打包至 Google Drive 同步。

## 曾考慮的替代方案（Considered Options）

- **繼續自製 3D 資產（Blender / Python 程式建模 / AI 生圖）**：美術品質與迭代速度遠落後於現成模組套件，且難以支撐大量隨機街區變化，故放棄。
- **保留三人即時跟隨小隊**：實測中跟隨隊友增加畫面雜訊與 AI 尋路負擔，改將多角色魅力轉移至「局內救援 → 局外養成與列車崗位支援」的 NPC 乘員系統。
- **將大型 `.glb` / `.fbx` 放進 Git LFS**：易受免費額度與跨機克隆頻寬限制，且不便隔離第三方非商用原型素材授權；改採 `assets_manifest.json` + Google Drive 版本化壓縮包更輕量可控。

## 影響（Consequences）

- **正面**：模組化街區天然契合隨機地圖生成；動作庫與角色模型解耦大幅降低後續換角與新增喪屍的成本；Git Repo 維持輕量高速；核心玩法目標明確，可立即分階段推進實作。
- **限制與注意事項**：
  - 商業發行前需將原型角色（`SummerCuteness`）替換為明確具備商用授權之人型角色模型（因已採 `SkeletonProfileHumanoid`，替換時無需重做 Mixamo 動作）。
  - 任何新增或修改外部素材的機器都必須遵循 `tools/pack_assets.py` 打包並同步更新 `assets_manifest.json` 與 Google Drive，且不得從 Git 移除 `.import` 與 `.tres`。
